# Pin policy: `==` for the SDKs and libraries whose next release changes behaviour
# (exchange, provider and chart clients); `~=` for libraries whose API is stable
# across minor releases, so a patch can land but the major line the bot was tested
# on cannot move. Version floors and compatibility caps for packages that arrive
# only as dependencies of these live in constraints.txt, which the launchers pass
# to pip with -c and scripts/check_requirements.py verifies alongside this file.
# A floor would let a fresh install resolve a newer major than the venv runs (CI
# proved it: torch and pydantic came in one minor ahead), so every entry states a
# bound instead. Comments name what holds a package back; do not lift a hold
# without the test run and the CHANGELOG entry.
